# issue-gold15-bprime-p1-gpuecho —— 失败面记录（P1 打通过程踩坑实录）
# 说明：以下为实测/实录的失败形态，是 solution.md §2 根因的依据。

[1] 二进制帧被 tty 行规约破坏（run89 wire log 实锤）
  现象：host gpuecho_host.py 报
      ValueError: bad frame len 1581276736
  1581276736 = 0x5E405E40 = "^@^@"
  机理：/dev/hvcN 是 tty，默认 ICANON|ECHO——
      NUL(0x00) 被回显成 "^@" 两字符；0x17(WERASE) 触发退格序列，
      二进制帧内容被 caret 转义/编辑序列改写，长度头随之损坏。
  修法：guest open 后 cfmakeraw(&tio)+tcsetattr（gpuchan_test.c），帧即透明。

[2] adb 窗口不开（gold-15 nativehang/watchdog 重启循环）
  现象：run_p1.sh 后台轮询无输出；adb devices 显示 127.0.0.1:5911 offline。
  机理：对已注册 offline 端点反复 `adb connect` 不生效。
  修法：循环内先 `adb disconnect 127.0.0.1:5911` 再 `adb connect` 复位；
      （另注：run_p1.sh 会 2s 一次 disconnect/connect，反而干扰已开窗口——
      窗口已开时应直接手动跑测量，不再轮询。）

[3] zsh 变量分词坑（工具脚本 bug，非链路问题）
  现象：zsh:1: command not found: adb -s 127.0.0.1:5911
  机理：ADB="adb -s …" 后 $ADB 在 zsh 下不按空格分词，整串当命令名。
  修法：直接写全命令（或显式 ${=ADB}）。

[4] hvc6 编号冲突（会话合并丢失）
  现象：gpuecho 通道曾占用 hvc6，被宿主振动（cdh-haptic）工作覆盖丢失。
  修法：gpuecho 迁至末位 hvc11 重新加回，不改既有编号；host 侧脚本同步改 /dev/hvc11。
