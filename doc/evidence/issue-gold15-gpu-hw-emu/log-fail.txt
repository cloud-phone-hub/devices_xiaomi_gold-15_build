## F2 ✗ 假设「stock 官方内核可以直接当云机基座」

判据：官方 `boot.img` 内嵌 config（`raw/official-kernel-config-key.txt`）

```
CONFIG_VIRTIO=y   CONFIG_VIRTIO_PCI=m   CONFIG_VIRTIO_BLK=m   CONFIG_VIRTIO_CONSOLE=m
（无）CONFIG_VIRTIO_NET   （无）CONFIG_VIRTIO_INPUT   （无）CONFIG_VIRTIO_GPU
（无）CONFIG_DRM_VIRTIO_GPU   （无）CONFIG_VIRTIO_SND
```
`system_dlkm` 78 个 GKI 模块中 virtio 只有 `virtio_balloon/blk/console/pci/pci_legacy_dev/pci_modern_dev/vmw_vsock_virtio_transport`。

结论：**否（至少不是直接可用）**。换官方内核会同时失去现行云机的**网络/输入/显示（virtio-gpu）/音频**虚拟化，
必须连 MTK 显示子系统一起仿真，或重建官方内核源码并补 virtio 开关（且要维持符号 CRC 不变）。

## F3 ✗ 假设「vermagic 字符串不同 ⇒ stock 模块无法加载」

厂商模块 `…-g4d05d8779bfd-4k` vs 官方内核 `…-ge56cf6b09cca-ab15511674-4k`，看似铁证。

判据：`kernel/source/kernel/module/version.c:77-88`

```c
/* First part is kernel version, which we ignore if module has crcs. */
int same_magic(const char *amagic, const char *bmagic, bool has_crcs)
{
	if (has_crcs) {
		amagic += strcspn(amagic, " ");
		bmagic += strcspn(bmagic, " ");
	}
	return strcmp(amagic, bmagic) == 0;
}
```

结论：**假设错误**。有 `modversions` 时只比较第一空格之后的段（`SMP preempt mod_unload modversions aarch64`），
版本串被忽略。**真正的门是符号 CRC（F1）**；本项勘误避免了把力气花在"对齐版本串"上。

## F4 ✗ 假设「宿主侧缺 GPU 通路，需要从零造宿主渲染」

判据：P1 现场（宿主产物 + `-device help`）

结论：**否**。darwin 已有 `virgl_render_server` + MoltenVK + virglrenderer 的 venus host-pointer 补丁；
linux 已有 `vhost-user-gpu` + 独立 renderer。缺口只在于**没有 Mali 设备模型**与**没有 Mali ISA 翻译器**。

## F5 ✗ 假设「厂商 kbase 里有 MTK 平台接入点，需要逐条仿真」

判据：子代理对 kbase 源码的检索 —— `grep -rnw -e mtk_gpufreq -e mtk_gpu_hal -e mtk_gpu_qos -e ged -e mediatek kbase/drivers kbase/include` → **0 命中**

结论：**否**。上游 kbase 与平台只有通用回调（`struct kbase_platform_funcs_conf` / `kbase_pm_callback_conf`，
devicetree 平台的 `kbase_platform_dvfs_event` 本身即空桩）。MTK 专有部分全在**厂商自己的 fork** 里
（对应 F1 的 46 个 MTK 符号），因此 V2 档（用上游 kbase）**不需要**在驱动侧仿真 MTK 平台。

## F7 ✗ 假设「客机换 Mesa 栈即可拿到完整图形能力（含 Vulkan）」

判据：外部调研（`raw/external-prior-art.md` §2.3）

- Mesa Panfrost 支持矩阵里 **G57/G68（Valhall v9）的 Vulkan 一栏为空**；Collabora 2025-07 原文：第一代 Valhall (V9) "currently
  completely lacking support"。
- 结论：**否**。路线 E 只能覆盖 **GLES**（≈3.1）侧；Android 15 上 `ro.hwui.use_vulkan=true` 的 Vulkan 路径仍只能靠厂商 Mali。
  方案 §3.5 已按此修正（原稿"完整且成熟"是错的）。

## F8 ✗ 假设「ARM Fast Models 的 Mali 模型可直接采购落地」

判据：外部调研（`raw/external-prior-art.md` §2.5）

- 公开型号只有 **Mali_G710 / Mali_G715（v10+）**，**无 v9/G57**；GRM 默认只输出**渐变图案**；
  GGA+GRM 集成 Mali 驱动**必须自写 `libnwhal`**（ARM 不提供宿主 GPU 后端）；**GGA 已弃用**；无 macOS 形态。
- 结论：**否**。方案新增 §3.6 路线 F 并判为"不可直接落地"。

## F9 ✗ 假设「Mali ISA 已经有可用的开源反编译器/翻译器」

判据：外部调研（`raw/external-prior-art.md` §2.2）

- 只有 disassembler（Mesa `ISA.xml`/`v9.xml` 驱动）；**没有任何** Mali ISA → SPIR-V/NIR/LLVM 翻译器；
  Apple Air 格式无公开汇编器，唯一官方 IR 入口是 metal-shaderconverter（DXIL/SPIR-V → Metal）。
- 结论：**否**。T3（真渲染）在 Apple Silicon 宿主上**无先例、无现成工具链**；方案 §4 G4 与 §6 R6/R7 已据此改写，
  §8 增加"下一轮 0：否定性验证"作为先决动作。
