## P5 设备模型接口面（kbase r49p0 源码，pristine 上游）

- MMIO 抽象唯一落点：`kbase_reg_read/write32/64`（kbase/hw_access/Kbuild:29-33 编译期二选一）
- 3 条中断：tag JOB=0/MMU=1/GPU=2（kbase/backend/gpu/mali_kbase_irq_internal.h:27-29），byname 获取（mali_kbase_core_linux.c:439-475）
- 寄存器块：GPU_CONTROL 0x0000 / JOB_CONTROL 0x1000（JS 槽 0x1800+n*0x80）/ MMU_CONTROL 0x2000（AS 0x2400+n*0x40）
- 硬依赖：`GPU_COMMAND=SOFT_RESET` → `GPU_IRQ_RAWSTAT.RESET_COMPLETED(1<<8)`（500 ms 超时，pm_driver.c:3296-3400）
- 身份：GPU_ID 必须 0x09030010（product_id 0x09000003，r0p1）
- 工程量：必须档 ≈2 250–4 050 行 C；次要 ≈700–1 600；可桩 ≈80–150
- 风险：`/lib/firmware/valhall-1691526.wa`（TTRX_3485）——`THREAD_FEATURES[31:30]=SOFTWARE(3)` 或 r0p1 可绕开

## P7 外部先例与生态调研（2026-10-12，来源见 raw/external-prior-art.md）

| 问题 | 结论 |
|---|---|
| 有公开的"寄存器级仿真 Mali + 桥接宿主 GPU"先例吗 | ❌ 无（唯一同类实践 = NO_MALI + 自加 platform_device，与本仓库现行路线同构、不出画） |
| QEMU 有 Mali 设备模型吗 | ❌ 无（本仓库 QEMU 源码检索 + `-device help` 双证） |
| gfxstream/VirGL/Venus 能驱动 stock Mali 栈吗 | ❌ 不能（API 重映射，要求客机跑它们自己的 ICD） |
| 有 Mali ISA → SPIR-V/NIR/LLVM 翻译器吗 | ❌ 无（只有 disassembler；Apple Air 无公开汇编器，唯一官方 IR 入口 = metal-shaderconverter） |
| 客机换 Mesa 栈（panfrost/panvk）能覆盖吗 | ⚠️ 只能 GLES；**PanVK 对 Valhall v9 完全不支持** |
| ARM Fast Models 有 Mali 模型吗 | ⚠️ 有 GRM/GGA，但公开型号只有 G710/G715（v10+）、默认渐变图案、需自写 `libnwhal`、GGA 已弃用、无 macOS |
| 宿主换真 Mali 的先例 | ✅ 通用形态成熟；MT8370/Genio 700（Mali-G57）已有 panfrost 主线补丁；MT6833 stock 栈无公开先例 |
| 关键风险论据 | ⚠️ "没有真 Mali 做 oracle，寄存器级仿真的正确性无法收敛"（Collabora） → 抬升路线 C 优先级 |
