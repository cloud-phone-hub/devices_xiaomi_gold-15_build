## 坑 1：手工构造 saturate 位算错位域（暴露的是「位域归属」而非「有无拦截」）

IADD 组带 `<saturate/>`（`Flag("saturate", 30)`，bit30），未建模须 fail-loud。
初版想验证该守卫，手工算出：

    base = 0x00a0c40000000b0a
    错：0x00a0c40000000b0a | (1 << 30) = 0x00a0c44000000b0a   # ← 算成 bit38

实际它落在 **widen 掩码（`0xF@36`）** 内，于是报的是「源修饰」而非 saturate：

    错误：IADD.u32 带未建模的源修饰（0x00a0c44000000b0a）   # ← 位域归属不符

改用 Python 表达式直接构造 `base | (1<<30)` 得正确字 `0x00a0c40040000b0a`，重跑命中：

    错误：IADD.u32 带未建模的 saturate 修饰（0x00a0c40040000b0a）
    exit=2

教训：**验证 fail-loud 时必须用表达式构造字，不手算位移**；错误信息里的「修饰名」就是位域归属的
自证——名字不符即说明位算错。IADD 组 saturate=30、widen=36，二者相邻，手算极易串位。

## 坑 2：`LSHIFT_OR.i32` 的 `shift` 操作数编码无法从 ISA 唯一定论（主动排除）

同属整数族的 `LSHIFT_OR.i32`/`RSHIFT_AND.i32`（真机 3 条）本可顺带放开，但其第三操作数
`shift` 用 ISA 的 `lanes="true"` 元数据（编码非常规 src 域，`asm.py`/ISA.xml 无法只凭静态元数据
确证其位域）：

    $ python3 va2spirv.py fl_shift.bin ...
    错误：不支持的指令 LSHIFT_OR.i32（P2 子集外）
    exit=2

决策：**宁可 fail-loud 也不猜编码**。需先做「真机字 + `asm.py` 试装」双向核验再放开（见 §6 遗留 #1）。
`fl_shift.bin` 真机字 `0x00b4c8011105c004` 保留作后续核验素材。

## 坑 3：fail-loud 不能取消

本批是「自包含 ALU」，容易顺手放开更多同 opcode 形态（如把整数组的 swizzle/widen/saturate 一并译）。
但三种修饰未建模，一旦放过将静默产生**语义偏差**（饱和丢失、源修饰丢失）。
故 `main()` 分派前**显式**对整数组做 saturate（bit30）守卫，`src_mod_mask()` 继续拦 widen——两条守卫均保留。

## 坑 4：zsh 不做无引号词分割 → 回归一度误报全 fail

回归脚本用 `local e="$@"; ./harness ... $e`。zsh 默认**不对未引用参数做词分割**，
故 `$e="255 0 0 255"` 被当成**单个**参数传给 harness → 参数个数不符 → 打印用法并 exit 1，
误报「8 用例全 fail」。改用 `${=e}`（zsh 显式分割）后全部失败 0 / exit 0。

教训：harness 用法报错时先核对**参数个数**，勿直接判成渲染失败；跨 shell 脚本须显式控制词分割。
