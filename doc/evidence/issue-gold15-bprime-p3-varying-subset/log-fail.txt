# log-fail —— 片元 varying 输入（LD_VAR_BUF_IMM）扩充踩坑记录

## 坑 1：staging 基址藏在 dest 域，但 ins.dests 为空
- 直觉：像普通指令一样从 `ins.dests` 取目标寄存器。但 ISA.xml 里 LD_VAR_BUF_IMM 组
  声明的是 `<sr write="true"/>`（staging），`dests` 为空，且 `valhall.py`
  有 `assert(len(dests)==0 or not staging)` —— 二者互斥。
- 语法上也不同：汇编操作数是 **staging 列表**（`@r0:r1:r2:r3`），不是单个 dest。
- 修正：新增 `decode_meta()`，直接按 **staging 元数据**取基址
  （`sr.start=40` + `sr.encoded_flags=0x80`），连续数取 `staging_register_count`(bits33)。

## 坑 2：非 v4/src_f32 变体 raise 后以 traceback/exit 1 呈现
- `emit_varying` 对不支持的组合 `raise ValueError`，但 `main()` 未捕获 →
  Python traceback、**exit 1**，与既有 fail-loud（打印一行错误、**exit 2**）不一致。
- 修正：把指令翻译包进 `try/except ValueError` → 打印
  `错误：<指令> 翻译失败：<原因>` 并 `return 2`。
  实测 v2 变体：`错误：LD_VAR_BUF_IMM.f32 翻译失败：仅支持 v4（vector_size=1）`，exit 2。

## 坑 3：staging 连续寄存器须偶对齐（汇编期约束，非翻译期）
- `asm.py:214` 要求「连续 staging 寄存器须按寄存器对对齐」→ `@r1:r2` 会汇编失败。
- 本例用 `@r0:r1:r2:r3`（基数 0，偶对齐）规避；翻译期不重复该校验。

## 坑 4：byte order 别混
- 合成 bin（Mesa asm.py 输出）用 `<Q`（小端）读；真机 bin 用 `>Q`（大端）。
- 本轮合成 shader 走 `<Q`，与 va2spirv.py 的 `struct.unpack("<%dQ")` 一致。
