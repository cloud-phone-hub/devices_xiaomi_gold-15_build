# issue-gold15-bprime-p3-shift-subset —— 失败现场（log-fail）

采集环境：Apple M4 Pro / macOS；
spirv 工具：/Users/cuimingqiang/Library/Android/sdk/ndk/29.0.14206865/shader-tools/darwin-x86_64/

本批核心卡点是 **缩放常量的 SPIR-V 类型标签**，与移位指令本身无关；记录如下。

---

## 1) 失败现象：FMA 操作数类型不匹配（spirv-val exit 1）

初版用例用 `IADD_IMM.i32` 物化缩放因子 `1/255 = 0x3B808081`，想让整数结果 `×1/255` 落到 [0,1]：

    IADD_IMM.i32 r13, 0x0, #0x3B808081
    ...
    U16_TO_F32 r0, r4
    FMA.f32    r0, r0, r13, 0x0

翻译成功，但 `spirv-val` 报错：

    $ spirv-val --target-env vulkan1.1 /tmp/fl_scale.frag.spv
    error: line 36: GLSL.std.450 Fma: expected types of all operands to be equal to Result Type
      %29 = OpExtInst %float %13 Fma %27 %16 %float_0
    exit=1

（原始现场行号为 line 42 / `%35`，同一失败，行号随用例结构微变。）

## 2) 根因

`IADD_IMM.i32` 的发射器把结果登记为 **整数** SSA：`self.reg[r13] = ('ssa', id, 'int')`。
而 `FMA.f32` 通过 `val_to_ssa(opnd, "float")` 取操作数时，对 `('ssa', id, 'int')`
是 **SSA 直通、不做类型转换**（只有 `('const', bits)` 才会按目标位型物化常量）。
于是 `FMA` 的第 2 操作数 `%16` 是 `%int`，与结果类型 `%float` 不符 → SPIR-V 类型校验失败。

即：**用整数指令「拼」出的 32 位字，其 SSA 带 int 标签，不能当 float 用**。

## 3) 修复

改用 `MOV.i32` + **LUT 浮点常量** 物化缩放因子（`MOV` 会把 LUT 位型按目标 `float` 物化）：

    MOV.i32 r13, 0x3DCCCCCD      # LUT 0.1f（Immediates 表内），物化为 %float 常量

三个用例（`frag_shift` / `frag_shift_real` / `frag_shift_neg`）全部改为
`MOV.i32 r13, 0x3DCCCCCD` + `FMA.f32 rx, rx, r13, 0x0`，期望值相应改为
`round(int*0.1f*255)`（选用 int=2→51、int=6→153 等 round-to-even 无歧义值）。

修复后 `spirv-val` 6 模块全 PASS（见 [log-pass.txt](log-pass.txt) §4）。

## 4) 教训（写入 solution.md §2.5）

- **任意 32 位 float 常量必须用 `MOV.i32` + LUT 物化**，不可用 `IADD_IMM.i32`
  （后者产 int 标签；`val_to_ssa(_, "float")` 对 int SSA 直通 → 类型不匹配）。
- 缩放期望值须避开 `round-to-even` 歧义点（`int*0.1f*255` 落在 .5 的值），
  本批选用 `int=2→51`、`int=6→153`（干净），避开 `int=3→76/77`、`int=5→127/128`。
