# log-fail —— LD_VAR_BUF_IMM.f32 插值族放开（宽度/采样模式）踩坑记录

日期：2026-10-12

## 坑 1：SPIR-V 装饰编号 Centroid/Sample 误写为 43/44
- 直觉：采样位置修饰「像是」靠后的编号，写成 `DEC_CENTROID, DEC_SAMPLE = 43, 44`。
- 现象：`spirv-val` 报
  `error: line 7: End of input reached while decoding OpDecorate ... expected more operands after 3 words`。
- 根因：43 = `InputAttachmentIndex`、44 = `Alignment`，**两者都带操作数**，故解析器认为缺少操作数。
- 修正：改为 **`Centroid=16`、`Sample=17`**（SPIR-V 装饰枚举）。

## 坑 2：能力编号 SampleRateShading 误写为 33
- 直觉：顺着能力枚举数到 33。
- 现象：`spirv-dis` 把 `OpCapability` 显示成 **`CullDistance`**；
  `spirv-val` 仍报 `Operand 2 of Decorate requires one of these capabilities: SampleRateShading`。
- 根因：SPIR-V 能力枚举在 **16 处跳号**（`Pipes` 从 17 起），导致 32 之后的编号整体偏移 2：
  `ClipDistance=32`、`CullDistance=33`、`ImageCubeArray=34`、**`SampleRateShading=35`**。
- 修正：`CAP_SAMPLE_RATE = 35`。

## 坑 3：Sample 装饰需声明 SampleRateShading 能力
- `sample(2)` 映射到 `OpDecorate %v Sample` 后，若模块头未声明 `OpCapability SampleRateShading`，
  `spirv-val` 直接 FAIL：
  `error: line 8: Operand 2 of Decorate requires one of these capabilities: SampleRateShading`。
- 修正：`FragBuilder` 增 `need_sample_rate` 标志，`sample==2` 时置位，`build()` 里追加该能力。
- 补充实证：harness 管线为 `SAMPLE_COUNT_1` 且未开 sample shading，**MoltenVK 仍接受该模块**并正常出图
  （1 采样时 sample 位置即像素中心，插值结果等价 center）；故未改 harness 设备特性即通过逐像素。

## 坑 4：byte order 别混（承接上批，重申）
- 合成 bin（Mesa `asm.py` 输出）用 `<Q` 小端读；真机 shader bin 用 `>Q` 大端读。
- 本轮合成 shader 走 `<Q`；真机那条 f32 是**先大端解码得到字 `0x005c82841208003d`，再当标量喂给
  `asm.py` 反汇编命中**，两种字节序不混用。

## 坑 5：v4 专用假设「index/16」不能外推到 v2/v3
- 上批把 `Location = index/16` 写死（只对 v4 成立）。真机那条 index=8、v2 宽，
  若沿用 /16 会得到 Location 0（错），实际应为 `8/(2*4)=1`。
- 修正：`Location = index / (comps*4)`，并**要求 index 按宽度对齐**，否则 fail-loud
  （`index 须按向量宽度对齐(index=4, span=16)`）。
