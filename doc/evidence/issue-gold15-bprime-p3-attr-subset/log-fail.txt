=== CDH gold-15 B′ P3：LD_ATTR_IMM 顶点属性通路建模验证日志（失败面与守卫） ===

[1] 元数据 register_format 缺失导致的格式未识别
- 现场：初版 decode_meta() 仅提取了 vector_size 与 staging_register_count，未包含 register_format（offset 24, size 3），导致 meta.get("register_format") 为 None，无法区分真机 9 条 f32 与 1 条 f16。
- 根因：Valhall 中 LD_ATTR_IMM 的目标寄存器格式由 bits 24..26 编码（2=f32, 3=f16）。
- 解决：在 decode_meta() 扫描列表中加入 "register_format"，正确提取 2 与 3。

[2] r63 寄存器未定义即读（活性跟踪拦截）
- 现场：在编写 attr_f16 用例时，试图使用 "FMA.f32 r2, r0.h0, r63, r63" 物化加宽分量，翻译器报错：
  "错误：FMA.f32 翻译失败：r63 未定义即被读取"（exit 2）。
- 根因：硬件上 r63 常被用作只读零寄存器，但 va2spirv 的 FragBuilder 要求每个被读取的虚拟寄存器必须在此前经历过写入定义，防止未初始化寄存器产生野指针或未绑定 SSA。
- 解决：改用规范的 LUT 常量 "0x0"（即 Valhall 的 mode 3 LUT 0 常量，值 0.0f）：
  "FADD.f32 r2, r0.h0, 0x0"，既符合 ISA 语义，又通过活跃性检查。

[3] table 索引非 1 显式 fail-loud 拦截（fl_attr_table）
- 测试代码：LD_ATTR_IMM.v4.f32.slot0 @r0:r1:r2:r3, r60, r61, index:0x0, table:0x2
- 执行输出：
  [fl_attr_table] 翻译 exit 2（预期 fail-loud=2）
  错误：LD_ATTR_IMM 翻译失败：LD_ATTR_IMM 仅支持 table=1（属性表），当前 table=2
- 验证结论：非法或未建模的属性表索引被可靠拦截，严防静默错译。

[4] 负向对照像素比对失败（attr_neg）
- 测试用例：frag_attr_neg.asm（生成标准 (51, 102, 153, 255) 渲染），在 run_matrix.py 中故意赋予错期望 (255, 0, 0, 255)。
- 执行输出：
  逐像素比对：256x256，三角形内 7812 px、外 0 px（边界带跳过），失败 7812
  exit 1
- 验证结论：离屏逐像素比对具备极高灵敏度，测试通道无假阳性。
