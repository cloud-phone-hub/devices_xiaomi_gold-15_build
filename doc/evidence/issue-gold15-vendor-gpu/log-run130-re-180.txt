# run130 obj[0x180] 逆向取证（2026-10-15）——模型修正：两类对象混同，值=DDK 常数

## 结论（三条）
1. obj[0x180]=612 是 DDK 编译期 .rodata 常数（0x2f0d18={612,2}），唯一非零写点=构造
   函数 0x2173d34（new(0x1af0) 的 C++ 类）；唯一清零点=reset 虚方法 0x216e074，
   **清零后类内无回填路径**。不存在任何 ioctl 出参 → obj[0x180] 的数据通路。
2. **两类对象混同修正**：播种器 0x2170654 所属 = 0x1af0B C++ 类（vptr@0，字段
   0x100/0x108/0x178/0x180/0x278/0x280/0x6b0-0x6d4）；run128 实拍 obj = 0x15bf8B
   cmar 大对象（obj[0]=mali fd、[0x654..0x65c]=eventfd、[0x6e8/0x6ec]=兜底计数/sem）。
   两者仅在 0x6d0 等偏移巧合重叠（字段直方图交叉验证：互不访问对方特有字段）。
   run128 从未实测 obj[0x180]，"180=0" 是由 budget=0 反推的遗留假设——**不成立**。
3. **真活体为 0 的是 cmar 大对象 budget@0x6d0**，其播种=DDK 内部硬编码 32（cmar-init
   状态机 step 0xe @0x1cee094-0x1cee3ac：32 次 0x48B 节点分配入 free-list，
   0x1cee3a8 `mov w8,#0x20; str w8,[obj,#0x6d0]`），亦非 ioctl 内核字段。

## budget=32→0 的候选成因（下一 run 靶子）
- (a) 清理/销毁链 0x1cee800 跑过（0x1cee934 双清 budget/兜底计数；调用点=init 失败
  0x1cee7b4、**销毁链 0xb40c40**、尾巴 0x1ceeb5c）——销毁链与 cmar 线程存活并存
  （线程未 join）恰可复现 run128 快照态；
- (b) dispatch 漏耗：0x1cf2800/0x1cf2838 budget--（type>4/1 路径无条件递减），
  而 producer 0x1cf2a00 对 type 2/3 直接 ret 不回收 → 146 atom 场景可能漏耗归零。

缺口"可补**（该值不接内核数据）。内核差异只可能间接触发（某 ioctl 返回错误 →
DDK 走 reset/销毁链 → 清零后无回填）。下一 run 取证=钉死清零触发者：
