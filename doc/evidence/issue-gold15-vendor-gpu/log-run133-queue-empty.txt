## 结论（三连跳后的收敛态）
1. **停泊假说（run133 靶子）死**：两队列皆空——节点不是"入队未派发"，而是**派发后被
   无回收路径吞掉**（dispatch default 分支 node+0x10∉0..5 直接 ret 不回收，或处理尾
   未达 0x1cf2a00 回收）；
2. **内核事件面彻底无罪**：run128"146 atom 从未消费"= 内核事件**零读**，32 个 pop
   全部来自 **DDK 内部工作项**（eventfd 唤醒携带的 type 0/1/4/5 入队即 pop）——
   事件码、24B 结构、(27a-27d) 暂存回放（run133-RE 已核对结构逐字段对齐）全部排除；
3. **type 来源（run133-RE）**：type 是 DDK 内部工作项类别（0-5，入队 0x1cf2770 写
   node+0x10），**非内核事件码位域**；type 2/3 是内嵌节点**从不 pop**（run130
   "type2/3 不回收"表述修正：那是内嵌设计，不耗池）；
4. **真机不漏**（run131 健康）+ **同一 DDK 二进制**（run131 md5 对账）⇒ 差异只能
   在**运行环境触发的 DDK 内部状态**：头号嫌疑=**udata.blob[1] 野值**（run133-RE：
   blob[1] 是 DDK 内部对象指针，type-1 处理器 `blr [x0+0x20]` 间接调用）——我方
   内核 11.45 atom 布局解析 11.46 DDK 提交的 udata 位置若错位（(12c) 已证 atom
   字段迁移），回显事件的 blob[1] 为垃圾 → 间接调用野地址/状态错乱 → 工作项
   带错 type 派发 → default 分支吞节点。

## 遗留（run134 靶子）
1. **udata 透传对账**（头号）：核对我方内核从 72B/64B atom 取 udata（blob[0/1]）的
   偏移 vs 11.46 DDK 写入偏移（(12c) 线索：+0x31 新字段/字段迁移）；错位即根因；
2. **活体纵览**（次选）：kill SF 逼重启后 200ms×60 采样 budget/freelist/队列，
   看 32→0 是瞬间（init 期）还是随活动渐漏——区分"入队即错型"与"处理尾吞"；
3. 修复面（定案后择一）：内核 udata 按 11.46 布局取值回显（对齐 DDK）；或对
   blob[1] 做合法性钳制（需先证实语义，run129 教训：语义未明不动二进制）。

## 取证技巧增补（§28.5 之外）
- obj 定位一轮法：`set -- $(dd skip=$sp count=512 | od -A n -t x8)`；obj=saved-x19
  通常在 sp+0x48（`obj=${10}`）；scudo tag 剥除用字符串 `0x${obj#??}`（免算术）；
- od `head -N` 截断坑：每行 16B，head 行数×16=覆盖字节，拍 0x700 需 ≥112 行；
  区域定点补拍用 skip=绝对地址（0x 直传 dd）。
