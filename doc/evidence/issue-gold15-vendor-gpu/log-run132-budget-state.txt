# run132 云机 cmar 池活体字段实拍（2026-10-15）——漏耗假说 (b) 实锤，cleanup (a) 排除

## 取证路径
实例控制通道（145，POST /cmd + SSE /events，guest root/pioneer）→ SIGSTOP cmar 线程
→ /proc/<tid>/mem 栈 dump → 候选指针逐个读字段（scudo tag 已剥）。

## obj 定位（三点指纹命中）
obj = 0x7459d5a400（栈上 4 个 scudo 堆候选之一，两次出现=saved x19 形态）
- obj+0x000 = 0x0000000a（mali fd=10）✓
- obj+0x654..0x65c = 0x0b/0x0c/0x0d（eventfd 11/12/13）✓（与 run128 指纹同构）
- 栈 pollfd 数组（sp+0x60）：fd=10 events=POLLIN + fd=11/12/13 —— 与 run128 帧逐字吻合

## 活体字段（obj+0x6d0 区 32B）
| 偏移 | 值 | 语义 |
|---|---|---|
| 0x6d0 | **0x00000000** | budget = 0（根因状态复现） |
| 0x6d4 | 0x00000000 | cap = 0 |
| 0x6d8/0x6dc | 0x00000000 ×2 | free-list 头 = NULL（**节点被 pop 光**） |
| 0x6e0/0x6e4 | 0x00000000 ×2 | — |
| 0x6e8 | **0x00000020 = 32** | 播种值**原封未清** |
| 0x6ec | 0x00000040 = 64 | sem/容量类字段 |

## 判定
1. **(a) cleanup/销毁链假说排除**：cleanup 0x1cee934 语义=连带清 budget[0x6d0]
   与 兜底计数[0x6e8]；实拍 0x6e8=32 **未清零** → cleanup 没跑过。
2. **(b) 漏耗假说实锤**：32 节点被**精准 pop 光**（freelist=NULL、budget=0），
   播种记账原封（0x6e8=32）——非回收消费路径吃掉全部节点：
   run130 逆向两漏点=dispatch 消费路径 type 2/3 producer 0x1cf2a00 **直接 ret 不回收**、
   type>4/1 路径**无条件 budget--**。节点一去不返 → read 门 min(budget,8) 永关
   → 146 mali 事件永滞留（run128）→ 死自旋。
3. **事件语义差异假说升级**（run130 §26.3"内核差异间接触发"具体化）：
   云机虚拟 kbase 交付的事件**类型组合**可能与真机不同（如把 JS 完成事件打成
   2/3 型）→ DDK 走非回收路径 → 漏耗。真机（run131）cmar 睡 ppoll 健康 =
   真机事件回收正常、池不漏。
4. 附加观察：SF 762→773 销毁重建（cmar tid 820→810）——SF 重启循环存在，
   但池漏耗与之独立（新池同样 32→0）。

## 工具备注（换机避坑）
- guest sh 算术是 **32 位**（`$((0x...))` 64 位地址截断成负数）→ 64 位偏移
  一律把十六进制串**直传 toybox dd 的 skip**（支持 0x），勿经 shell 算术；
- /proc/<tid>/syscall 停止态只有 3 字段（`-1 <sp> <pc>`），sp=$2 非 $8；
- cmd.exec JSON 里禁单引号（用 `set -- $(cat ...)` 取字段）。

## 遗留（run133 靶子）
1. **钉死 32 个漏耗事件的类型/来源**：核对我方内核 (27a-27d) 事件暂存回放补丁的
   事件**类型字段**是否与真机 kbase 语义一致（对账 uapi 事件类型编码）；
   或内核侧事件出队点加限次类型日志（安全、无语义改动）实测类型分布；
2. 修复面候选（择一，定案后动）：内核侧事件类型对齐真机语义（让 DDK 走回收
   路径）；或 DDK 回收语义确认后内核适配（type 2/3 若为真机也存在的正常流，
   则漏耗在真机为何不发生=回收来源差异）；
3. §27.4 遗留 3（两个 md5 版本来源对账）维持登记。
