# run136 事件出入队双点实测（2026-10-15）——事件在流、回显忠实；矛盾收敛为「有 pop、零回收」

## 构建
wire-kbase v88-evprobe2 注入 (29a) EV-ADD（kbase_event_post 入队）/ (29b) EV-GET
（kbase_event_dequeue 出队）双点打点，限次 64、纯日志无语义改动；
全链 build-kernel→boot→vendor_dlkm→super→pack exit 0；新实例 146。

## 实测（runtime/gold-15/146/qemu.log）
EV-ADD=64  EV-GET=64（双双打满限次 ⇒ 真值 ≥64，上界未知）
```
EV-ADD atom=1 code=0x1 blob0=0xb400007ccaeaf040 blob1=0xb400007eabd57000
EV-ADD atom=2 code=0x1 blob0=0xb400007ccaeaf040 blob1=0xb400007eabd58000
EV-ADD atom=5 code=0x1 ... blob1=0xb400007eabd57000
EV-GET atom=1 code=0x1 blob0=0xb400007ccaeaf040 blob1=0xb400007eabd57000  ← 与 ADD 逐条一致
EV-GET atom=2 code=0x1 ... blob1=0xb400007eabd58000
```
code=0x1 = BASE_JD_EVENT_DONE。

## 判定（模型第二次翻转）
1. **「146 事件零读」论死**：内核事件**在正常交付**（EV-GET 走到 kbase_event_dequeue，
   64 条）；budget=0 与「146 滞留」自洽为**果**——读门 min(budget,8)=0 → DDK 停读 →
   内核事件积压；
2. **「udata 回显错值」死**：blob0/blob1 逐条 ADD==GET，回显忠实（削弱 run136-RE
   头号嫌疑「回显值错位」）。

## 核心矛盾（阻塞「直接修 pop」）
事实：budget 归 0、freelist 空、sem 计数=初值（0 次回收）、0x6e8 原封。
⇒ 至少存在一条 **「pop/派发但零回收」** 路径在跑；但「洪泛超容后失序」vs「派发吞没」
未定。run136-RE 证 type-1 handler 单出口→回收尾、无早退 ⇒ 中间仍有一环未抓到。
附注：run133 读 obj+0x660 队列「全 0」——空 list_head 应为自指非零，**疑第三次
仪器偏移误读**（前两次：0x180、0x6c8），须复核。

## 遗留

  开机 30s 高频采样 budget/freelist（抓 32→0 转折点与对应事件速率）；
