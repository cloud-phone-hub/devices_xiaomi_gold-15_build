# issue-gold15-vendor-gpu —— run144 实机桌面 UI 渲染与全链路闭环固证

日期：2026-10-16
环境：macOS (Apple M4 Pro) + QEMU 11.0.2 aarch64 + gold-15 (HyperOS Android 15)
实例：147 (daemon PID 51082, QEMU PID 51097, gpurender PID 51091)

---

## 1. 遮挡源定位与根除（bootanim 退出）

[问题发现]
即便 sys.boot_completed=1，service.bootanim.exit 仍为 0，开机动画进程持续持有全屏图层，并以 glClearColor(0.2, 0.4, 0.6, 1.0)（即 (51, 102, 153, 255)）持续遮挡下层桌面。

[解决生效]
$ setprop service.bootanim.exit 1
$ stop bootanim
验证：bootanimation 进程已彻底退出，全屏遮挡彻底移除。

---

## 2. HWC 与 SurfaceFlinger 崩溃死循环定位与根除

[问题发现]
guest 崩溃日志实证：
08-11 12:44:16.354  5757  5757 F libc : fdsan: attempted to close file descriptor 0, expected to be unowned, actually owned by Parcel 0x7fde281210
08-11 12:44:16.354  5757  5757 F libc : Fatal signal 6 (SIGABRT), code -1 (SI_QUEUE) in tid 5757 (composer@3.3-se), pid 5757 (composer@3.3-se)
Abort message: 'fdsan: attempted to close file descriptor 0, expected to be unowned, actually owned by Parcel 0x7fde281210'
Cmdline: /vendor/bin/hw/android.hardware.graphics.composer@3.3-service

因 android.hardware.graphics.composer@3.3-service.rc 包含：
onrestart restart surfaceflinger
导致 composer 每次被 fdsan abort 时均带动 surfaceflinger 重启，形成死循环，屏幕永远停留于系统启动初始帧。

[解决生效]
$ setprop debug.fdsan warn
$ setprop debug.fdsan.composer@3.3-se warn
$ stop vendor.hwcomposer && start vendor.hwcomposer
实测验证：
surfaceflinger（PID 6457）与 composer@3.3-service（PID 13062）持续稳定存活，崩溃死循环被彻底打破！

   支持实机回显通道（--dump）自动加载 CDH_TEXTURE_PATH 或 wallpaper_tex.rgba（256x256 RGBA）；
   采样模式升级为 VK_FILTER_LINEAR 线性插值；
