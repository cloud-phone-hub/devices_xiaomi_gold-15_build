# run131 真机对照探针（2026-10-15）——真机链路健康，云机卡点=DDK 池 budget=0 定案

## 现场
真机 Redmi Note 13 5G（2312DRAABC / gold，magisk su，USB adb）
SF pid=975；RenderEngine tid=1097；mali-cmar-backe tid=1175

## 对照表（真机 vs 云机 run128）
| 项 | 真机（本次实测） | 云机（run128 实拍） |
|---|---|---|
| cmar 线程态 | **S**（3×1s 采样稳定） | **R**（死自旋） |
| cmar wchan | **do_sys_poll**（syscall 73 ppoll，nfds=4） | libc poll 立返（revents=POLLIN 恒真） |
| cmar 内核栈 | do_sys_poll → __arm64_sys_ppoll（阻塞等事件） | —（用户态自旋） |
| RenderEngine 线程态 | S / futex_wait_queue（正常） | 卡 drawLayers |
| 事件流 | **健康**：poll 阻塞=队列空、读门开、事件被消费 | 146 事件滞留 → poll 恒 POLLIN → cbz budget 跳 read → 死锁 |
| cmar 池 budget | 未做内存实测（线程态已足判别：poll 阻塞 ⇒ budget>0、消费正常） | budget[0x6d0]=0、cap=0 |

## 判定
1. **真机该链路是通的**（cmar 睡在 ppoll 上等事件，事件到达才醒、读门消费）；
2. **云机卡点确认 = DDK cmar 事件池 budget=0**（播种被跳过/清零，run130 两候选：
   销毁链 0xb40c40/清理 0x1cee800 被触发 vs dispatch 漏耗），**不是**
   "kbase job 事件回传"机制本身缺失；云机内核 146 事件滞留是 budget=0 的**果**
   （读门永关积压）而非因。
3. 选项 2（真机对照）达成目的：卡点环=DDK 用户态池播种/回收链，云机环境差异
   触发了回收路径（候选：某 ioctl 返回差异令 DDK 走 reset/销毁）。
