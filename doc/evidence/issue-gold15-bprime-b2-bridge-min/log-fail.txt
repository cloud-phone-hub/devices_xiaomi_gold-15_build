# log-fail.txt —— 失败面/拦截面留档（2026-10-14，issue-gold15-bprime-b2-bridge-min）

## 1. 回执段未闭环（0 done / 30 timeout，run106 统计）
`done_count=0 timeout_count=30 q_count=30`：30 条请求全部 3s 兜底超时放行。
- host 只收到 3 帧（seq=9/10/11，且均为 status=1 语义失败回执）；
- 请求记录逐字节核对**三端对称**（内核 put_be32 序列化 / helper get_be32 /
  host struct ">4sIQIIIIIII"，host 解析值与 q 行逐字段一致）→ 线格式无错；
- 写回路径（RP01→write(/proc/cdh_gpumbox)→done）**一次都没被行使到**：
  收敛为 helper 存活窗口问题——gold-15 guest 重启循环每次杀死 helper
  （进程不随 reboot 存活），另 debuggerd/crash_dump ptrace 冻结嫌疑
  （(17) 保护名单只含 SF/composer/system_server，不含 gpumbox_bridge）。
- 教训：回执段要么给 helper 保活（init 服务/自动重启），要么把 done/拒绝原因
  打进 dmesg（写回 -EINVAL 各分支当前静默，下批补诊断行）。

## 2. helper 鲁棒性缺陷（run105 定案，已修）
- 丢一帧=永久卡死：host 未连时写 hvc11 的帧被丢，helper 阻塞在 frame_read
  等永不来的回执 → 后续请求全部积压超时（run105 现象）；
- 已修：响应 poll 2.5s 超时跳过 + 全部错误分支 break→continue（不退循环）；
  待复核：poll 2.5s 与 host 渲染延迟的匹配（va2spirv 实测 50-90ms/次，余量足）。

## 3. /dev 权限陷阱（run102 定案，已修）
misc 设备 `.mode=0666` 无效——Android ueventd 按自身规则把 /dev 节点重置 0600，
shell 用户 helper 被拒（Permission denied）；procfs 不受 ueventd 管
（/proc/ged 0666 先例）→ mailbox 换 /proc/cdh_gpumbox 0666，`ls -l` 实证生效。

## 4. 构建缓存陷阱（复犯旧教训）
改 wire-kbase.sh/桥源后未 bump recipe → prebuilt 缓存命中「复用内核 Image」，
两处修复根本没编进去（run101 实证：设备仍 0600）；bump 后重建才生效。
教训（复发强化）：**改内核侧源码必 bump build_recipe**。

## 5. 真机 UI shader 语义缺口（新定案）
host 收到的 3 条真机 shader 全部翻译失败：`TEX_SINGLE` / `VAR_TEX_BUF_SINGLE`
（纹理采样指令）不在 P3 捕获的 160 条子集内——P3 语料是当时探针抓到的 shader，
UI 合成 shader 以纹理采样为主。**纹理族建模（TEX/VAR_TEX + sampler + 纹理
描述符 ABI）是「像素回显」的前置语义缺口**，归下一批；fail-loud 语义不变
（status=1 回退兜底图层，不回错误像素）。
